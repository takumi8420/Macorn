# 読む場所と順番

パスはすべてリポジトリのルート（このスキルを置いたフォルダ）からの相対パス。セッションの作業ディレクトリがルート以外のときは、`.claude/skills/catch-up/` の3つ上をルートとみなす。

## 1. 共通

| 順 | ファイル | 読む目的 | 読み方 |
| --- | --- | --- | --- |
| 1 | `AGENTS.md` | 案件の一覧（Step 1）、確定している前提 | 最初は「フォルダ構成」の表だけ。案件が決まったら「確定している前提」以降 |
| 2 | `CHANGELOG.md` | 経緯（きっかけ・意図・方針）と変更内容 | 新しい順。対象案件の見出しだけ。「共通」は対象案件のパスが出てくるものだけ |

CHANGELOG のエントリの形（記載ルールは `AGENTS.md`）：

```markdown
## YYYY-MM-DD

### {案件名}：{作業の要約}

- **きっかけ**：依頼者・会話など
- **意図・方針**：なぜその形にしたか
- 追加 `パス` — 何をどうしたか
```

## 4. 記録漏れの点検

CHANGELOG にある対象案件の最新日付以降に更新されたファイルを探す。ビルド出力と OS のメタファイルは除く。

```bash
# リポジトリのルートで実行。YYYY-MM-DD は CHANGELOG の対象案件の最新日付
find . -type f -newermt YYYY-MM-DD \
  -not -name '.DS_Store' \
  -not -path './build/*' \
  -not -path './.git/*' \
  -not -path '*/xcuserdata/*' | sort
```

同じ日付の中での前後は判定できないので、最新日付「当日」のファイルは CHANGELOG の記載と目視で照合する。
